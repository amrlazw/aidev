2 · Model memory — bytes per parameter

Rule of thumb: VRAM ≈ weights + KV cache + activations + ~20–30% headroom. A 7B FP16 model ≈ 14 GB weights → comfortably serves on one 24 GB GPU (A10, L4, 4090). A 70B FP16 ≈ 140 GB → needs 2× H100/H200, or 1× H100 quantized to INT8/FP8.

3 · KV cache formula (decode memory)

KV bytes ≈ 2 × L × Hkv × head_dim × seq_len × batch × bytes_per_elem
(2 = keys + values · FP16/BF16 = 2 bytes, FP8 = 1, FP4 = 0.5)

Why it matters: long contexts + big batches blow up memory. This is why vLLM's PagedAttention and GQA (grouped-query attention) exist.

4 · Rough serving throughput (published benchmarks)

  • 7–8B model, single A100/H100, batch 16–32 with vLLM: ~1,500 – 3,500+ tokens/sec aggregate across concurrent requests.
  • 70B model, FP8 on H100 (TensorRT-LLM / vLLM): ~1,800 – 6,000 tokens/sec aggregate, depends on input/output split.
  • Every number is a function of batch size, prompt length, generation length, and quantization — always say "it depends" and show the math.

5 · Inference sizing — back-of-envelope

  1. Peak concurrency: users × % online × avg requests each → concurrent requests.
  2. Demand: concurrent requests × (avg prompt tokens + avg output tokens) ÷ target response seconds = tokens/sec needed.
  3. GPUs: tokens/sec needed ÷ per-GPU throughput (from §4) × safety headroom (1.5–2×).
  4. Fit check: does (weights + KV + overhead) fit in VRAM at that concurrency? If not: bigger GPU, quantize, or split tensor-parallel.
  5. Sanity: latency targets — TTFT (time to first token, < 1–2 s feels instant) and TPOT (per-token time for streaming).

6 · Units & conversions

  • 1 GB/s = 8 Gb/s · 1 GiB = 1.074 GB · ~1 token ≈ 3–4 characters ≈ 0.7 English words.
  • PCIe Gen5 x16 ≈ 64 GB/s · H100 NVLink ≈ 900 GB/s (≈14× PCIe) · NVSwitch connects 8 GPUs in a pod.
  • 1 H100 ≈ 700 W → a dense rack of 8×H100 servers ≈ 40–60 kW incl. cooling → liquid cooling territory.
  • 1 H100 80 GB ≈ 10x a full-size laptop GPU for LLM inference (rule of thumb, not gospel).
